# رابط کاربری رویش

این پوشه یک پروژه Next.js و React است که برای سه سامانه، سه اجرای مستقل دارد. هر اجرا به API خودش متصل است؛ ورود به یکی، ورود به دو سامانه دیگر محسوب نمی‌شود. سامانه‌ها داده مشترک یا درگاه ادغام ندارند.

## اجرا

ابتدا بک‌اند موردنظر را طبق راهنمای اصلی مخزن اجرا کنید. سپس در این پوشه:

```powershell
npm ci
npm run dev:personnel
# یا در ترمینال مستقل:
npm run dev:inventory
npm run dev:commerce
```

| سامانه | رابط کاربری | API |
|---|---|---|
| پرسنلی | http://127.0.0.1:3001 | http://127.0.0.1:8001/api/v1 |
| انبار | http://127.0.0.1:3002 | http://127.0.0.1:8002/api/v1 |
| بازرگانی | http://127.0.0.1:3003 | http://127.0.0.1:8003/api/v1 |

برای اجرای خروجی آماده:

```powershell
npm run build
npm run start:personnel
# start:inventory و start:commerce در ترمینال‌های جداگانه
```

حساب‌های نمونه فقط در محیطی نمایش داده می‌شوند که بک‌اند `SEED_DEMO=true` داشته باشد. ورود با نام کاربری و گذرواژه واقعی به API انجام می‌شود. همه داده‌های نمونه ساختگی‌اند.

## مسیر مطالعه کد

۱. `src/app/page.tsx` نام سامانه را از متغیر محیطی می‌گیرد.

۲. `src/components/App.tsx` نشست، فهرست بخش‌ها، دسترسی نقش‌ها و پوسته رابط را مدیریت می‌کند. توکن هر سامانه در `sessionStorage` خودش قرار می‌گیرد و در بازیابی صفحه با `/auth/me` اعتبارسنجی می‌شود.

۳. `src/lib/resources.ts` تعریف صریح فیلدها، ستون‌ها، انتخاب‌ها و مسیر API هر بخش است. برای نمونه، کارکنان به `/employees` و مشتریان به `/customers` وصل‌اند. این تعریف‌ها از تکرار سه رابط تقریباً مشابه جلوگیری می‌کنند.

۴. `ResourceTable.tsx` جست‌وجو، فیلتر، صفحه‌بندی، دریافت CSV و نمایش جزئیات را اجرا می‌کند. جست‌وجو و صفحه‌بندی در سرور انجام می‌شوند. خروجی CSV تمام ردیف‌های مطابق فیلتر را دریافت می‌کند.

۵. `ResourceForm.tsx` فیلدهای تعریف‌شده را نمایش می‌دهد و گزینه‌های وابسته را از API همان سامانه دریافت می‌کند. ایجاد با `POST` و ویرایش با `PATCH` انجام می‌شود؛ در ویرایش فقط فیلدهای تغییرکرده ارسال می‌شوند. فرم پیشنهاد قیمت، ویرایشگر ردیف‌های خدمات دارد.

۶. `src/lib/workflows.ts` عملیات هر وضعیت را مشخص می‌کند؛ مانند تأیید مرخصی، دریافت خرید، بازگشت تجهیزات و ابطال صورتحساب. `WorkflowForm.tsx` توضیح و تأیید نهایی کاربر را می‌گیرد و نتیجه واقعی سرور را نمایش می‌دهد.

۷. `src/lib/api.ts` تنها محل ساخت آدرس API، افزودن توکن، مهلت درخواست و تبدیل خطای سرور به پیام رابط است. خطای اتصال با اطلاعات ساختگی جایگزین نمی‌شود.

## قراردادهای رابط

- تاریخ ورودی ISO و میلادی است؛ نمایش تاریخ با `Intl` و تقویم فارسی انجام می‌شود. دوره محاسبه حقوق، ماه میلادی است.
- همه مبالغ، عدد صحیح به تومان‌اند.
- انتخاب مشتری، قرارداد، کالا و مانند آن از API همان سامانه می‌آید.
- شناسه کارمند در انبار و بازرگانی، مرجع UUID سامانه پرسنلی است؛ نام کارمند نیز به‌عنوان سابقه همراه ثبت می‌شود. دریافت خودکار کارمند از سامانه دیگر جزو این رابط نیست.
- محدودیت نقش در رابط برای وضوح است؛ کنترل اصلی مجوز و اعتبارسنجی کسب‌وکار در بک‌اند انجام می‌شود.
- تغییر گذرواژه همه نشست‌ها را در سرور باطل می‌کند و رابط ورود دوباره را نمایش می‌دهد.

## تنظیم برای سرور

در محیط تولید می‌توانید همان خروجی build را با سه مقدار مستقل `ROYESH_SYSTEM` اجرا کنید. `API_URL` در زمان اجرا خوانده می‌شود و باید آدرس عمومی API باشد که مرورگر کاربر به آن دسترسی دارد:

```powershell
$env:API_URL = 'https://personnel-api.example.com/api/v1'
npm run start:personnel
```

`API_BASE` و `NEXT_PUBLIC_API_URL` نیز پشتیبانی می‌شوند. متغیرهای `NEXT_PUBLIC_PERSONNEL_URL`، `NEXT_PUBLIC_INVENTORY_URL` و `NEXT_PUBLIC_COMMERCE_URL` برای لینک جابه‌جایی بین دامنه‌های آنلاین هستند و باید هنگام build تنظیم شوند. برای انتشار عمومی، HTTPS و تنظیم دقیق CORS بک‌اند لازم است. Dockerfile خروجی standalone را با کاربر غیر root اجرا می‌کند.

## بررسی کیفیت کد

```powershell
npm run typecheck
npm run format:check
npm run build
```

پوشه‌های `.next*` و `node_modules` خروجی ابزارند؛ کد اصلی در `src` قرار دارد. فونت وزیرمتن از بسته npm و به‌صورت محلی سرو می‌شود.
