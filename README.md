# رویش | مدیریت شرکت نرم‌افزاری

سه سامانه مستقل **پرسنلی، انبار و بازرگانی** با بک‌اند Python/FastAPI و رابط فارسی Next.js/React. این مخزن شامل APIها، پایگاه داده، رابط‌ها، داده نمونه، آزمون‌ها و راهنمای تحویل به تیم ادغام است.

## سه سامانه در سه پوشه مشخص

| سامانه | پوشه اختصاصی بک‌اند و راهنمای اجرا | راهنماهای Word | قرارداد API |
| --- | --- | --- | --- |
| **۱ پرسنلی** — کارکنان، استخدام و حقوق | [services/personnel](services/personnel/README.md) | [۵ راهنمای پرسنلی](deliverables/word-guides/01-personnel) | [personnel.json](docs/openapi/personnel.json) |
| **۲ انبار** — خرید، موجودی و تجهیزات | [services/inventory](services/inventory/README.md) | [۵ راهنمای انبار](deliverables/word-guides/02-inventory) | [inventory.json](docs/openapi/inventory.json) |
| **۳ بازرگانی** — مشتری، قرارداد و مطالبات | [services/commerce](services/commerce/README.md) | [۵ راهنمای بازرگانی](deliverables/word-guides/03-commerce) | [commerce.json](docs/openapi/commerce.json) |

```text
services/
  personnel/    # سامانه پرسنلی
  inventory/    # سامانه انبار
  commerce/     # سامانه بازرگانی
frontend/       # کد رابط مشترک با سه اجرای مستقل
shared/         # ابزارهای پایه مشترک برای سه بک‌اند
deliverables/word-guides/
  01-personnel/ # پنج فایل Word پرسنلی
  02-inventory/ # پنج فایل Word انبار
  03-commerce/  # پنج فایل Word بازرگانی
```

هر سامانه سرور، دیتابیس، نشست و پورت خودش را دارد. اشتراک سورس رابط و ابزارهای پایه به معنی اشتراک داده نیست. در پوشه هر سامانه، `start.cmd` فقط API و رابط همان سامانه را اجرا می‌کند. نصب اولیه از ریشه با `setup.cmd` است. [راهنمای رابط مشترک](frontend/README.md) فرمان‌های مستقل هر سه رابط را نشان می‌دهد.

این مخزن سورس و داده نمونه ساختگی را نگه می‌دارد؛ فایل‌های دیتابیس محلی، نشست‌ها، فایل‌های محیطی خصوصی، پشتیبان‌ها و خروجی build در Git قرار نمی‌گیرند. انتشار مخزن در گیت‌هاب، برنامه را خودکار آنلاین نمی‌کند.

## اجرای سریع روی ویندوز

پیش‌نیاز: Python 3.11 یا جدیدتر و Node.js 24 یا جدیدتر، همراه npm. آزمون‌های رابط از اجرای مستقیم TypeScript در Node 24 استفاده می‌کنند. نصب اولیه اینترنت می‌خواهد. اجرای بعدی به اینترنت احتیاج ندارد؛ فونت فارسی داخل برنامه نصب می‌شود.

1. بار اول فایل `setup.cmd` را اجرا کنید. نصب کتابخانه‌ها و ساخت فرانت‌اند انجام می‌شود.
2. فایل `start.cmd` را اجرا و پنجره آن را باز نگه دارید.
3. آدرس‌های زیر را در مرورگر باز کنید. با Ctrl+C در پنجره اجرا یا اجرای `stop.cmd`، همه سرویس‌هایی که این راه‌انداز شروع کرده متوقف می‌شوند.

| سامانه | رابط کاربری | مستندات تعاملی API |
| --- | --- | --- |
| پرسنلی | http://localhost:3001 | http://localhost:8001/docs |
| انبار | http://localhost:3002 | http://localhost:8002/docs |
| بازرگانی | http://localhost:3003 | http://localhost:8003/docs |

فرمان معادل: `python scripts/manage.py setup` و سپس `python scripts/manage.py start`. اجرای یک سامانه: `python scripts/manage.py start --service inventory`. گزارش خطاها در پوشه `.runtime` قرار می‌گیرد.

اگر مخزن اصلی PyPI در شبکه شما در دسترس نبود، می‌توانید برای همان نصب مقدار `PIP_INDEX_URL` را به آینه معتبر تغییر دهید؛ تنظیم سراسری رایانه لازم نیست. نصب این محیط با آینه Aliyun انجام شده است.

## ورود نمونه

این حساب‌ها فقط در حالت محلی `SEED_DEMO=true` روی دیتابیس خالی ساخته می‌شوند. داده‌ها و سازمان نمایش‌داده‌شده ساختگی‌اند.

| نقش | نام کاربری | رمز عبور |
| --- | --- | --- |
| مدیر سامانه | admin | admin12345 |
| کارشناس | manager | manager12345 |
| کارمند | staff | staff12345 |

سه سامانه حساب و نشست جدا دارند. کارمند پرسنلی فقط پرونده، حقوق و درخواست‌های خودش را می‌بیند؛ در انبار به فهرست کالاها و در بازرگانی به اطلاعات خواندنی مجاز دسترسی دارد. کارشناس گردش‌های تجاری را انجام می‌دهد و فقط مدیر سامانه کاربران را مدیریت می‌کند.

## امکانات

- **پرسنلی:** واحد و سمت، پرونده کارمند، نوع همکاری و وضعیت استخدام، قرارداد استخدامی، ثبت و تأیید مرخصی/مأموریت، تشویقی و جریمه، صدور فیش و ثبت پرداخت حقوق.
- **انبار:** تأمین‌کننده، کالاهای تعدادی و تجهیزات سریال‌دار، خرید و تأیید و دریافت، گردش ورود/خروج، تحویل به کارمند و برگشت، بازنشسته‌کردن تجهیزات، گزارش موجودی و حداقل موجودی.
- **بازرگانی:** مشتری، خدمات شرکت، پیشنهاد قیمت چندردیفی، ارسال و پذیرش، قرارداد پروژه، صورتحساب، ثبت دریافت بانکی/نقدی/چک، مانده و مطالبات.
- **عمومی:** داشبورد از اطلاعات واقعی دیتابیس، جست‌وجو، صفحه‌بندی، خروجی CSV، فرم ایجاد و ویرایش، کنترل نقش در API، تغییر رمز، خروج و ابطال نشست، سابقه عملیات.

ثبت «پرداخت» در این پروژه به معنی ثبت سابقه است؛ اتصال بانکی یا درگاه پرداخت وجود ندارد. حقوق با فرمول آموزشی محاسبه می‌شود و موتور بیمه/مالیات نیست. دوره حقوق و فیلدهای API میلادی ISO هستند؛ تاریخ‌ها در رابط فارسی نمایش داده می‌شوند. مبالغ با عدد صحیح تومان ذخیره می‌شوند.

## معماری و مطالعه کد

| مسیر | مسئولیت |
| --- | --- |
| `services/personnel` | مدل‌ها، اعتبارسنجی‌ها، API و نمونه داده پرسنلی |
| `services/inventory` | مدل‌ها، عملیات اتمیک موجودی و نمونه داده انبار |
| `services/commerce` | پیشنهادها، قراردادها، صورتحساب و دریافت‌ها |
| `shared` | اتصال دیتابیس، ورود، نقش‌ها، ثبت رویداد و صفحه‌بندی |
| `frontend/src` | رابط مشترک خوانا که در سه نمونه مستقل اجرا می‌شود |
| `tests` | آزمون‌های HTTP با دیتابیس جدا برای هر آزمون |
| `migrations` | ایجاد و تغییر نسخه ساختار دیتابیس هر سرویس |
| `docs` | تحلیل، قرارداد API و راهنمای ادغام/استقرار |

مسیر یک درخواست را از route در فایل `app.py` یا `routes.py` دنبال کنید: schema ورودی را بررسی می‌کند، منطق تجاری مجوز/قواعد را کنترل می‌کند و SQLAlchemy تغییر را در تراکنش ذخیره می‌کند. پاسخ JSON به فرم یا جدول React برمی‌گردد. برای عملیات ساده لایه‌های غیرضروری ساخته نشده است.

سه API در اجراهای مستقل، سه دیتابیس مجزا دارند. کد ابزارهای پایه و کد رابط بازاستفاده می‌شود؛ هیچ سرویس برای اجرای مستقل به سرویس دیگری درخواست نمی‌زند. تیم ادغام بعداً اعتبارسنجی مرجع کارکنان، SSO، دروازه و پنل مشترک را اضافه می‌کند.

پنج راهنمای Word اختصاصی هر سامانه شامل معماری، دیاگرام دیتابیس، بک‌اند، فرانت‌اند و کاربری/API در `deliverables/word-guides` قرار دارند. [فهرست راهنماها](docs/word-guides.fa.md) ساختار این مجموعه را توضیح می‌دهد. بسته `deliverables/royesh-15-word-guides.zip` هر ۱۵ فایل را در سه پوشه فارسی دارد.

## توسعه دستی

از ریشه مخزن:

```powershell
.\.venv\Scripts\python.exe -m uvicorn services.personnel.app:app --reload --port 8001
```

در ترمینال دیگر، از پوشه `frontend`:

```powershell
npm run dev:personnel
```

برای دو سامانه دیگر به‌ترتیب `inventory` و `commerce` و پورت‌های جدول را استفاده کنید. پوشه build حالت توسعه هر سامانه جدا است. پس از تغییر کد فرانت‌اند، برای اجرای production محلی دوباره `npm run build` انجام دهید.

## بررسی و نگهداری

`check.cmd` یا `python scripts/manage.py check` آزمون‌های بک‌اند، آزمون‌های فرانت‌اند و بررسی TypeScript را اجرا می‌کند. ساخت فرانت‌اند با `npm run build` داخل `frontend` است.

SQLite به‌طور پیش‌فرض در `data/*.db` ذخیره می‌شود. حذف این پوشه داده‌ها را پاک می‌کند؛ برای شروع مجدد، اول سرویس‌ها را متوقف کنید و نسخه پشتیبان بگیرید. تهیه نسخه پشتیبان امن از SQLite در حال اجرا با `python scripts/backup.py` ممکن است. نسخه‌های پشتیبان شامل داده‌های حساس‌اند و در Git قرار نمی‌گیرند.

برای استقرار آنلاین، متغیرهای محیط، PostgreSQL، مهاجرت، HTTPS و تنظیم آدرس APIها را طبق [راهنمای استقرار](docs/deployment.fa.md) انجام دهید. حساب‌های نمونه برای انتشار عمومی مناسب نیستند. [راهنمای تیم ادغام](docs/integration.fa.md) مرز مسئولیت و قراردادها را توضیح می‌دهد.

[ممیزی جامع امکانات](docs/feature-audit.fa.md) فهرست بخش‌ها و اصلاحات و [گزارش بررسی](docs/verification.fa.md) نتیجه ۹۴ آزمون بک‌اند، ۱۶ آزمون فرانت‌اند، پوشش موفق ۹۹ مسیر/روش API و بررسی مرورگر را ثبت می‌کنند. برای ساخت بسته سورس مستقل از کتابخانه‌های نصب‌شده، `python scripts/package_source.py` را اجرا کنید.
